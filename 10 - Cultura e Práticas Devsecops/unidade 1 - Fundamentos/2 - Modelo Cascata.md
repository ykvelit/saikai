# Modelo Cascata

- Passo a passo
    - Análise de requisitos
        - Requisitos  
        - Prazos do projeto

    - Design do Sistema
        - Projeto lógico 
            - Layout 
            - Modelo de dados
        - Projeto físico 
            - Hardware 
            - Software

    - Implementação
        - Codificação
        - Teste unitário

    - Teste do Sistema
        - Integração das unidades de código em um único programa
        - Teste de integração

    - Implantação do Sistema
        - Lançamento para o mercado ou cliente

    - Manutenção do Sistema
        - Melhorias
        - Correções

- Requisitos
    - Definem o que um sistema deve fazer e sob quais restrições
    - Requisitos funcionais 
        - Representam o que o sistema deve fazer
    - Requisitos não funcionais
        - Representam sob quais restrições, que são as características que ele deve ter para funcionar bem

- Vantagens
    - Os requisitos do produto são esclarecidos na fase inicial, tornando as etapas de planejamento e desenvolvimento gerenciadas e bem documentadas
    - O custo do produto pode ser estimado com mais precisão
    - Cada fase é bem definida e, portanto, confortável de manter. As fases são concluídas sequencialmente
    - Os prazos dos produtos podem ser cumpridos porque os clientes geralmente não adicionam novos requisitos ao projeto

- Desvantagens
    - É um modelo de alto risco, tornando-o impróprio para projetos complexos e orientados a objetos
    - É muito difícil fazer alterações no código quando o desenvolvimento da aplicação chega à fase de testes
    - Atrasa a entrega do produto porque não são criados protótipos intermediários e o produto é entregue no final do ciclo
    - Caso o cliente fique insatisfeito com o produto, o desenvolvimento do produto deverá ser reiniciado, resultando em atraso e custos
